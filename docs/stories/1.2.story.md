# STORY-1.2: Hook gate-enforcer — push só com gate registrado

**Status:** Done
**Épico:** 1 — Release v0.2
**Criada em:** 2026-07-11
**Score de validação:** 8/10

## Por quê (contexto de negócio)

FR-6 do PRD / Constituição Art. III: hoje o gate é disciplina de fluxo, não bloqueio determinístico. Um push pode sair sem veredito do reviewer. O gate-enforcer fecha essa brecha no mesmo padrão do push-authority.

## O quê (escopo)

Novo hook `hooks/gate-enforcer.cjs` registrado em `hooks/hooks.json` (PreToolUse, matcher Bash): quando um comando de push é detectado E autorizado (shipper), verifica se existe story em entrega com veredito PASS ou CONCERNS na seção `## Gate`.

**Não está no escopo:** validar a qualidade do veredito; bloquear commits locais; interpretar branchs/PRs.

## Critérios de aceite

- [x] AC-1: comando sem push → exit 0 imediato (não penaliza Bash comum — NFR-5)
- [x] AC-2: push (autorizado pelo shipper) com pelo menos uma story `Status: InReview` ou `Done` cuja seção `## Gate` contém `PASS` ou `CONCERNS` → exit 0
- [x] AC-3: push com stories em `docs/stories/` mas NENHUMA com gate PASS/CONCERNS → exit 2 + mensagem citando o Art. III e como registrar o gate
- [x] AC-4: projeto SEM `docs/stories/` (plugin usado em projeto sem método completo) → exit 0 com aviso em stderr (não bloquear quem não adotou stories)
- [x] AC-5: override explícito `FORGE_GATE_OVERRIDE=1` no comando → exit 0 (escape para emergência, logando aviso)
- [x] AC-6: payload ilegível → exit 0 (padrão de tolerância dos hooks, ver architecture.md §Hooks)

## Como (orientação técnica)

- Copiar o padrão de `hooks/push-authority.cjs` (stdin JSON → regex no `tool_input.command` → exit 0/2). Regex de push: reutilizar a mesma (`/\bgit\s+([\w-]+\s+)*push\b/` e `gh pr`).
- `docs/stories/` é relativo ao `cwd` do projeto onde o plugin roda — usar `data.cwd` do payload do hook se presente; fallback `process.cwd()`.
- Ler stories com `fs.readdirSync` + `fs.readFileSync`; detectar `Status:` e conteúdo sob `## Gate` com regex simples. Sem parser de Markdown (NFR-1).
- Registrar em `hooks/hooks.json` como segundo comando no mesmo matcher Bash (ver estrutura atual do arquivo).
- Ordem: push-authority roda primeiro (autoridade), gate-enforcer depois (mérito) — a ordem no array de hooks.json define isso.

## Notas de implementação

- Só age quando push/`gh pr` é detectado E autorizado (`FORGE_ACTIVE_AGENT=shipper`); push não-autorizado é deixado para o push-authority (evita mensagem de gate errada). Override de emergência: `FORGE_GATE_OVERRIDE=1`.
- `cwd` vem de `data.cwd` do payload (fallback `process.cwd()`); `docs/stories/` lido com `fs.readdirSync` filtrando `*.story.md`.
- Extração do bloco `## Gate` por fatiamento (heading → próximo `##`/`---`/fim) — JS não suporta a âncora `\Z`, então nada de regex com fim-de-string; sem parser de Markdown (NFR-1).
- Filtro: `Status` ∈ {InReview, Done} **e** `PASS`/`CONCERNS` no bloco Gate.
